# Mars Land — Maximum Profit Optimizer

A Node.js command-line application that calculates maximum achievable earnings by optimizing sequential property construction within a given time budget.

Developed for the Everquint Full Stack Developer Interview Assessment.

## Problem Statement

Mr. X owns unlimited land and can construct three types of establishments. Only one establishment can be under construction at any given time. Completed establishments generate revenue during their remaining operational time.

## Building Configuration

| Establishment       | Construction Time | Earnings per Time Unit |
| ------------------- | ----------------: | ---------------------: |
| Theatre (T)         |                 5 |                  $1500 |
| Pub (P)             |                 4 |                  $1000 |
| Commercial Park (C) |                10 |                  $2000 |

## Features

- Recursive brute-force algorithm.
- Backtracking-based construction exploration.
- Maximum earnings calculation.
- Multiple optimal building combinations.
- Duplicate solution elimination.
- Interactive command-line input.
- Command-line argument support.
- Input validation.
- Automated tests.
- Zero external dependencies.

## Algorithm

The brute-force algorithm recursively explores every profitable construction sequence.

For each construction decision, the earnings generated by the selected establishment are calculated as:

```text
earnings = remainingTimeAfterConstruction × earningsPerUnit
```

Backtracking restores the building counts after each recursive exploration.

A Map stores unique optimal building combinations.

### Complexity

- Time complexity: O(3^(n/4)) exponential upper bound.
- Space complexity: O(n + k), where k is the maximum number of retained optimal combinations during execution.

## Assumptions and Limitations

- Time units are non-negative integers.
- Land capacity is unlimited.
- Completed properties generate revenue while subsequent properties are under construction.
- Construction completed exactly at the deadline is excluded because it generates no revenue.
- Multiple optimal combinations are returned without duplicates.
- The brute-force implementation temporarily limits input to 50 time units to prevent excessive computation.
